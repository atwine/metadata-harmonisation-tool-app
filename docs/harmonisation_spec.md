## 1. What This Tool Does

The Metadata Harmonisation Tool is a research-data-management application used by public health researchers and data scientists. Its job is to help an operator map variables from multiple external study datasets onto a single canonical **codebook** so that data from disparate studies can be compared and pooled.

### Concrete example

A researcher has three cohort studies:

| Study A variable | Study B variable | Target codebook variable |
|---|---|---|
| `age_months` | `age_at_baseline` | `Age (years)` |
| `sex_01` | `gender` | `Sex` |
| `BMI_kg_m2` | `bmi_value` | `Body Mass Index` |

The tool:
1. Accepts the codebook (the authoritative variable list with descriptions).
2. Accepts each study's variable list (with optional real data samples and a PDF context document).
3. Uses an AI embedding model to semantically rank which codebook variables each study variable is most likely to represent.
4. Presents an operator with a review UI where they confirm, reject, or reconsider each suggested mapping.
5. Optionally lets the operator define a **transformation** (a math expression or categorical mapping) that converts raw study values into the target codebook format.
6. Exports the final mapping table and optionally a transformed dataset.

### Five wizard steps (maps directly to five pages/routes)

| Step | Name | Purpose |
|---|---|---|
| 1 | Upload Codebook | Upload `target_variables.csv` |
| 2 | Upload Studies | Upload one or more study variable lists + optional files |
| 3 | Initialise | Configure AI provider, run the recommendation engine |
| 4 | Map Studies | Human-in-the-loop review and confirmation of each variable mapping |
| 5 | Download Results | Export mapping CSV or transformed data ZIP |

### Key stack notes for the next developer

- **TanStack Router** (not React Router): routes live as files under `src/routes/`. The root layout is `src/routes/__root.tsx`. Route discovery is automatic — adding a file to `src/routes/` creates a new route. Do not create a manual router config.
- **TanStack Start**: the SSR wrapper around TanStack Router. The entry points are `src/start.ts` and `src/server.ts`. Do not replace these.
- **Tailwind v4**: uses `@tailwindcss/vite` plugin and `@theme inline` directive in `src/styles.css`. There is no `tailwind.config.js` — all theme tokens are defined in CSS. The eLwazi colour variables are already in `src/styles.css`.
- **Cloudflare Workers**: `wrangler.jsonc` is present. The app is structured for edge deployment. When running the dev server use `bun run dev`, not `npm run dev`.
- **No `src/api/client.ts` yet**: this file does not exist and must be created from scratch when wiring the backend.
- **TanStack Query is installed** (`@tanstack/react-query`) but not yet used anywhere. The `QueryClient` is set up in `__root.tsx` ready to go.

### Why this stack

- **FastAPI**: async-native, automatic OpenAPI docs, Pydantic validation throughout, very easy SSE for streaming progress.
- **TanStack Router + Query**: great for polling/optimistic updates; the mapping UI needs real local state that Streamlit cannot cleanly model.
- **Zustand**: lightweight; the wizard step state and transformation draft storage map perfectly onto Zustand stores.
- **No database**: the existing file-based design is correct for a single-operator research tool. A DB would add operational complexity for no benefit at this scale.

### 5.2 Codebook Router (`routers/codebook.py`)

#### `POST /api/codebook/upload`

Accepts a multipart CSV upload. Validates and saves to `input/target_variables.csv`. Deletes any cached embedding file so the next Initialise run re-embeds.

**Request:** `multipart/form-data` with field `file: UploadFile`

**Business rules (enforced here):**
- Max file size: 10 MB
- Must be valid UTF-8
- Must parse as CSV
- Must contain at least one of: `variable_name`, `description`
- Recommended columns: `dType`, `Categories`, `Unit`, `Unit Example` (warn if missing, don't reject)
- Duplicate `variable_name` or `description` values → warning in response, not rejection

**Response:**
```json
{
  "status": "ok",
  "row_count": 142,
  "columns": ["variable_name", "description", "dType"],
  "warnings": ["Recommended column missing: Unit", "Recommended column missing: Categories"]
}
```

**Error responses:**
- `400` — file too large, not UTF-8, not parseable, missing required columns
- `422` — Pydantic validation failure

**Implementation sketch:**
```python
@router.post("/upload")
async def upload_codebook(file: UploadFile = File(...)):
    content = await file.read()
    
    # Size check
    if len(content) > 10 * 1024 * 1024:
        raise HTTPException(400, "File exceeds 10MB limit")
    
    # UTF-8 check
    try:
        text = content.decode("utf-8")
    except UnicodeDecodeError:
        raise HTTPException(400, "File must be UTF-8 encoded")
    
    # Parse CSV
    try:
        df = pd.read_csv(io.StringIO(text))
    except Exception as e:
        raise HTTPException(400, f"Could not parse CSV: {e}")
    
    # Column validation
    cols = set(df.columns)
    if "variable_name" not in cols and "description" not in cols:
        raise HTTPException(400, "CSV must contain 'variable_name' or 'description' column")
    
    warnings = []
    for rec in ["dType", "Categories", "Unit", "Unit Example"]:
        if rec not in cols:
            warnings.append(f"Recommended column missing: {rec}")
    
    # Duplicate detection
    if "variable_name" in cols:
        dupes = df["variable_name"].astype(str).str.strip().str.casefold()
        dupes = dupes[dupes.duplicated(keep=False)].unique().tolist()
        if dupes:
            warnings.append(f"Duplicate variable_name entries: {dupes[:5]}")
    
    # Save
    Path("input").mkdir(exist_ok=True)
    df.to_csv("input/target_variables.csv", index=False)
    
    # Invalidate embeddings cache
    emb_path = Path("input/target_variables_with_embeddings.csv")
    if emb_path.exists():
        emb_path.unlink()
    
    return {"status": "ok", "row_count": len(df), "columns": list(df.columns), "warnings": warnings}
```

### 5.3 Studies Router (`routers/studies.py`)

#### `POST /api/studies/upload`

Accepts a multipart upload with multiple optional files.

**Request:** `multipart/form-data`
- `study_title: str` — study name (will be sanitised)
- `variables_file: UploadFile` — required, CSV of study variables
- `example_data_file: UploadFile` (optional) — CSV of real/synthetic data
- `context_pdf: UploadFile` (optional) — PDF context document

**Study title sanitisation:**
```python
import re
from pathlib import Path

def sanitise_study_name(raw: str) -> str:
    # Remove any character that is not alphanumeric, space, hyphen, or underscore
    clean = re.sub(r"[^\w\s\-]", "", raw).strip()
    clean = re.sub(r"\s+", "_", clean)   # normalise spaces to underscores
    if not clean:
        raise ValueError("Study title is empty after sanitisation")
    # Path traversal check
    resolved = (Path("input") / clean).resolve()
    if not str(resolved).startswith(str(Path("input").resolve())):
        raise ValueError("Invalid study name")
    return clean
```

**Variables CSV rules:**
- Must contain `variable_name` column
- `description` column optional (AI will fill blanks during Initialise)
- Duplicate `variable_name` → warning

**Example data CSV rules:**
- No required column structure; columns are variable names
- Max 100 MB

**PDF rules:**
- Max 50 MB
- First 4 bytes must be `%PDF` (magic bytes validation)

```python
def validate_pdf_magic(content: bytes) -> bool:
    return content[:4] == b"%PDF"
```

  "variable_count": 47,
  "has_example_data": true,
  "has_context_pdf": false,

### 5.4 Initialise Router (`routers/initialise.py`)

This is the most important backend route because it runs multiple long-running operations and must stream progress back to the frontend.

#### `POST /api/initialise/run` — SSE streaming endpoint

**Request body:**
```json
{
  "ai_config": {
    "provider": "openai",
    "chat_model": "gpt-4o-mini",
    "embedding_model": "text-embedding-3-small",
    "api_key": "sk-...",
    "request_timeout": 30
  },
  "init_prompt": "As an AI, you are given the task of translating short variable names...",
  "force_rerun": false
}
```

**Response:** `text/event-stream` (Server-Sent Events)

The frontend connects to this endpoint and displays a live progress log. Each event is a JSON object:

```
data: {"step": "pdf_conversion", "status": "running", "message": "Converting PDFs to text..."}

data: {"step": "pdf_conversion", "status": "done", "message": "PDFs converted."}

data: {"step": "descriptions", "status": "running", "message": "Generating descriptions for cohort_2019 (3/47)..."}

data: {"step": "embeddings", "status": "running", "message": "Embedding codebook variables..."}

data: {"step": "recommendations", "status": "running", "message": "Building recommendation index for cohort_2019..."}

data: {"step": "pid_date", "status": "running", "message": "Generating PID/Date recommendations for cohort_2019..."}

data: {"step": "complete", "status": "done", "message": "Recommendation engine finished."}
```

**Implementation pattern:**
```python
from fastapi.responses import StreamingResponse
import asyncio
import json

@router.post("/run")
async def run_initialise(body: InitialiseRequest):
    async def event_stream():
        def emit(step, status, message):
            return f"data: {json.dumps({'step': step, 'status': status, 'message': message})}\n\n"
        
        yield emit("pdf_conversion", "running", "Converting PDFs to text...")
        await asyncio.to_thread(convert_pdf_to_txt)
        yield emit("pdf_conversion", "done", "PDFs converted.")
        
        yield emit("descriptions", "running", "Generating variable descriptions...")
        # generate_descriptions runs per-variable; use a callback to stream progress
        await asyncio.to_thread(generate_descriptions, body.ai_config, body.init_prompt,
                                 progress_cb=lambda msg: ...)  # yield inside
        yield emit("descriptions", "done", "Descriptions generated.")
        
        yield emit("embeddings", "running", "Embedding variables...")
        await asyncio.to_thread(get_embeddings, body.ai_config)
        yield emit("embeddings", "done", "Embeddings complete.")
        
        yield emit("recommendations", "running", "Building semantic recommendations...")
        await asyncio.to_thread(get_recommendations)
        yield emit("recommendations", "done", "Recommendations ready.")
        
        yield emit("pid_date", "running", "Generating PID/Date recommendations...")
        await asyncio.to_thread(get_PID_date_recommendations)
        yield emit("pid_date", "done", "PID/Date recommendations ready.")
        
        yield emit("complete", "done", "Recommendation engine finished.")
    
    return StreamingResponse(event_stream(), media_type="text/event-stream")
```

> **Key design note:** All the core functions (`convert_pdf_to_txt`, `generate_descriptions`, etc.) must be refactored to accept an `ai_config` parameter rather than reading from `st.session_state`. This is the most important breaking change from the Streamlit version.

## 6. Core Business Logic

This section documents the exact logic of the most complex parts — the pieces that must be preserved exactly in the new system.

### 6.1 Recommendation Engine

The engine runs in four sequential phases during Initialise. Each phase is idempotent — it checks whether its output file already exists and skips if so (unless `force_rerun=true`).

#### Phase 1: PDF → Text

```python
from pdfminer.high_level import extract_text

def convert_pdf_to_txt():
    for study in list_studies():
        pdf_path = f"input/{study}/context.pdf"
        txt_path = f"input/{study}/context.txt"
        if os.path.exists(pdf_path) and not os.path.exists(txt_path):
            text = extract_text(pdf_path)
            with open(txt_path, "w") as f:
                f.write(text)
```

#### Phase 2: AI Description Generation

Fills in blank `description` fields in `dataset_variables.csv` using an LLM. Outputs `dataset_variables_auto_completed.csv`.

**The prompt is a few-shot conversation:**
```python
def build_prompt(init_prompt: str, variable_name: str, context: str, examples: dict) -> list:
    messages = [
        {"role": "system", "content": init_prompt},
        # Hard-coded few-shot examples to anchor the style
        {"role": "user",      "content": "variable name: Patient ID, context: 'Not available'"},
        {"role": "assistant", "content": "Patient Identifier (?)"},
        {"role": "user",      "content": "variable name: matdiag, context: 'Not available'"},
        {"role": "assistant", "content": "maternal diagnosis (?)"},
    ]
    # Add in-context examples from already-described variables in this study
    for var, (ctx, desc) in list(examples.items())[:3]:
        messages.append({"role": "user",      "content": f"variable name: {var}, context: {ctx}"})
        messages.append({"role": "assistant", "content": desc})
    
    messages.append({"role": "user", "content": f"variable name: {variable_name}, context: {context}"})
    return messages
```

**Context retrieval (RAG from PDF):**
The PDF text is split into 1000-character chunks. The chunk most semantically similar to the variable name (via cosine distance of embeddings) is retrieved as context.

```python
def split_text(text: str, chunk_size: int = 1000) -> list[str]:
    chunks = []
    while text:
        if len(text) <= chunk_size:
            chunks.append(text); break
        pos = text.rfind(" ", 0, chunk_size)
        if pos == -1: pos = chunk_size
        chunks.append(text[:pos])
        text = text[pos:].lstrip()
    return chunks

def get_relevant_context(var_name: str, chunks: list[str], chunk_embeddings: list, embed_fn) -> str:
    var_emb = embed_fn(var_name)
    if not var_emb or not chunk_embeddings:
        return "Not available"
    distances = [cosine(var_emb, e) for e in chunk_embeddings]
    return chunks[distances.index(min(distances))]
```

**Key behaviour:** Variables that already have a non-empty description are skipped. The `*` prefix on AI-generated descriptions marks them as machine-generated (distinguishable from human-provided ones in the CSV).

#### Phase 3: Embedding Generation

Embeds both `variable_name` and `description` for every variable in the codebook and each study.

```python
def embed_dataframe(df: pd.DataFrame, embed_fn) -> pd.DataFrame:
    # Deduplicate texts before calling the embedding API (perf optimisation)
    all_texts = pd.unique(
        pd.concat([df["variable_name"].astype(str), df["description"].astype(str)])
    )
    embed_map = {t: embed_fn(t) for t in all_texts}
    df["var_embeddings"]         = df["variable_name"].astype(str).map(embed_map)
    df["description_embeddings"] = df["description"].astype(str).map(embed_map)
    return df
```

Outputs:
- `input/target_variables_with_embeddings.csv`
- `input/{study}/dataset_variables_with_embeddings.csv`

#### Phase 4: Recommendation Generation

For each study variable, ranks all codebook variables by cosine distance. The distance formula weights description similarity more heavily than variable name:

```python
# Distance formula (lower = better match)
d = (0.8 * distance(study_desc_emb, codebook_desc_emb))
  + (0.2 * distance(study_var_emb,  codebook_var_emb))
```

This is done efficiently with numpy matrix operations rather than a per-pair loop:

```python
import numpy as np
from scipy.spatial.distance import cosine

def generate_recommendations(study_df: pd.DataFrame, target_df: pd.DataFrame) -> pd.DataFrame:
    # Parse stored embeddings (they're saved as stringified lists in CSV)
    def parse_embeddings(series):
        return [ast.literal_eval(x) if isinstance(x, str) else x for x in series]
    
    T_var  = np.array(parse_embeddings(target_df["var_embeddings"]),         dtype=np.float32)
    T_desc = np.array(parse_embeddings(target_df["description_embeddings"]), dtype=np.float32)
    
    # L2-normalise for efficient cosine via dot product
    def l2norm(mat):
        return mat / (np.linalg.norm(mat, axis=1, keepdims=True) + 1e-12)
    
    T_var_n  = l2norm(T_var)
    T_desc_n = l2norm(T_desc)
    
    recommendations, distances = [], []
    for i in range(len(study_df)):
        v_var  = np.array(parse_embeddings([study_df["var_embeddings"].iloc[i]])[0],         dtype=np.float32)
        v_desc = np.array(parse_embeddings([study_df["description_embeddings"].iloc[i]])[0], dtype=np.float32)
        
        v_var_n  = v_var  / (np.linalg.norm(v_var)  + 1e-12)
        v_desc_n = v_desc / (np.linalg.norm(v_desc) + 1e-12)
        
        d_var  = 1.0 - (T_var_n  @ v_var_n)
        d_desc = 1.0 - (T_desc_n @ v_desc_n)
        d      = 0.8 * d_desc + 0.2 * d_var
        
        idx = np.argsort(d)
        recommendations.append(list(target_df["description"].iloc[idx]))
        distances.append([float(x) for x in d[idx]])
    
    study_df["target_recommendations"] = recommendations
    study_df["target_distances"]       = distances
    return study_df
```

### 6.3 Transformation Engine

The transformation engine supports two modes:

#### Direct (arithmetic expression)

Uses `SafeEvaluator` — a hand-rolled AST walker that only allows `+`, `-`, `*`, `/`, unary minus, numeric constants, and the variable `x`. **No eval() is used anywhere.**

```python
class SafeEvaluator:
    _BINOPS = {ast.Add: op.add, ast.Sub: op.sub, ast.Mult: op.mul, ast.Div: op.truediv}
    _UNARYOPS = {ast.USub: op.neg}
    _ALLOWED_NAMES = {"x"}

    def eval_expression(self, expr: str, context: dict):
        tree = ast.parse(expr, mode="eval")
        return self._eval_node(tree.body, context)

    def _eval_node(self, node, context):
        if isinstance(node, ast.BinOp):
            op_fn = self._BINOPS.get(type(node.op))
            if not op_fn: raise ValueError(f"Operator not allowed: {type(node.op).__name__}")
            return op_fn(self._eval_node(node.left, context), self._eval_node(node.right, context))
        if isinstance(node, ast.UnaryOp):
            op_fn = self._UNARYOPS.get(type(node.op))
            if not op_fn: raise ValueError(f"Unary op not allowed")
            return op_fn(self._eval_node(node.operand, context))
        if isinstance(node, ast.Name):
            if node.id not in self._ALLOWED_NAMES: raise ValueError(f"Name not allowed: {node.id}")
            return context[node.id]
        if isinstance(node, ast.Constant):
            return node.value
        raise ValueError(f"Unsupported: {type(node).__name__}")
```

Pipeline for one value:
```python
def direct_convert(x, expression, source_dtype, target_dtype):
    x = dtype_cast(x, source_dtype)           # e.g. str → float
    x = SafeEvaluator().eval_expression(expression, {"x": x})
    return dtype_cast(x, target_dtype)
```

#### Categorical (dict lookup)

```python
def categorical_convert(x, mapping_str: str):
    # SECURITY: length limit before deserialization
    if len(mapping_str) > 10000:
        return np.nan
    mapping = ast.literal_eval(mapping_str)
    if not isinstance(mapping, dict):
        raise ValueError("Not a dict literal")
    mapping = {str(k): v for k, v in mapping.items()}  # normalise keys to str
    return mapping.get(str(x), np.nan)
```

#### dtype casting

```python
def dtype_cast(x, dtype: str):
    try:
        if dtype == "float":   return float(x)
        if dtype == "integer": return int(x)
        if dtype == "string":  return str(x)
        if dtype == "boolean": return bool(x)
        return x  # "other" or None → pass through
    except (ValueError, TypeError, OverflowError):
        return np.nan
```

## 8. AI Provider Abstraction

The `AIProviderWrapper` must be refactored slightly: instead of reading from `st.session_state`, it receives `AIConfig` as a constructor parameter.

```python
class AIProviderWrapper:
    def __init__(self, config: AIConfig):
        self.config = config
        self.request_timeout = config.request_timeout
        self._rate_limit_window = 60
        self._rate_limit_max = 60
        self._timestamps: deque = deque()
        self._lock = Lock()
    
    def generate_chat_response(self, messages: list[dict]) -> str: ...
    def generate_embedding(self, text: str) -> list[float]: ...
    def validate_connection(self) -> tuple[bool, str]: ...
```

### Provider support matrix

| Provider | Chat | Embeddings | Notes |
|---|---|---|---|
| Ollama | ✅ | ✅ | Local only; no API key |
| OpenAI | ✅ | ✅ | `text-embedding-3-small` is recommended |
| Anthropic | ✅ | ❌ | No embeddings API; must pair with a different provider for embeddings |
| Azure OpenAI | ✅ | ✅ | Requires deployment name + API version |

### Rate limiting

The wrapper enforces 60 requests/minute using a sliding window (deque of timestamps):

```python
def _check_rate_limit(self):
    with self._lock:
        now = time.time()
        # Evict expired entries
        while self._timestamps and self._timestamps[0] < now - self._rate_limit_window:
            self._timestamps.popleft()
        if len(self._timestamps) >= self._rate_limit_max:
            raise AIProviderError("Rate limit exceeded")
        self._timestamps.append(now)
```

### Retry with exponential backoff

```python
def _retry(self, fn, *args, **kwargs):
    self._check_rate_limit()
    for attempt in range(self.max_retries):
        try:
            return self._with_timeout(fn, self.request_timeout, *args, **kwargs)
        except Exception as e:
            if attempt == self.max_retries - 1:
                raise AIProviderError(f"Failed after {self.max_retries} attempts: {e}")
            time.sleep(self.retry_delay * (2 ** attempt))
```

## 9. Security Requirements

All of these are carried over from the existing implementation and must be preserved:

### Input validation

| Check | Limit | Location |
|---|---|---|
| Codebook CSV file size | 10 MB | Upload endpoint |
| PDF file size | 50 MB | Upload endpoint |
| Example data CSV | 100 MB | Upload endpoint |
| PDF magic bytes | `%PDF` prefix | Upload endpoint |
| Study name characters | `[^\w\s\-]` stripped | Study upload |
| Path traversal | Resolve + prefix check | Study name, all file ops |
| Operator name length | 100 chars | Mapping save |
| Notes length | 500 chars | Mapping save |
| Transformation instructions length | 500 chars | Mapping save |
| Categorical mapping string length | 10 000 chars | Before `ast.literal_eval` |
| Embedding string length | 100 000 chars | Before `ast.literal_eval` |

### Expression safety

Never use `eval()`. All transformation expressions go through `SafeEvaluator`. Any node type other than `BinOp`, `UnaryOp`, `Name{"x"}`, or `Constant` raises `ValueError`.

### SQL injection (DuckDB)

In the refactored version, DuckDB queries on CSV files should use parameterised queries or simply use pandas (which avoids the SQL layer entirely for this use case). If DuckDB is retained, use the sanitiser:

```python
def sanitise_sql_string(value: str) -> str:
    return str(value).replace("'", "''")
```

### Whitelisted deletions

File deletion (Clear Workspace) is only permitted inside `input/`, `results/`, `logs/`, `preprocess/` directories, verified by resolving to absolute path and checking the prefix.

### API keys

API keys are never written to disk or logged. They arrive in request bodies, are used in-memory, and are discarded. The audit log records `provider_info` which only includes provider name, model names, and a boolean `has_api_key` — never the key itself.

## 11. Gaps and Gotchas — Critical Implementation Details

These are behaviours that are NOT obvious from the high-level spec and that a re-implementer would get wrong without reading the original source. Read this section before coding.

### 11.1 `ModelConfig.get_client()` — exact client construction

```python
# config.py (existing) — must be preserved exactly in backend/core/config.py

class AIProvider(Enum):
    OLLAMA = "ollama"
    OPENAI = "openai"
    ANTHROPIC = "anthropic"
    AZURE_OPENAI = "azure_openai"

class ModelConfig:
    def get_client(self):
        if self.provider == AIProvider.OLLAMA:
            client = ollama.Client(host=self.base_url)
            client.list()  # test connection immediately; raises if Ollama not running
            return client

        elif self.provider == AIProvider.OPENAI:
            # SECURITY: validate key format before constructing client
            if not re.match(r'^sk-[A-Za-z0-9]{20,}$', self.api_key):
                raise ValueError("Invalid OpenAI API key format")
            return openai.OpenAI(api_key=self.api_key, base_url=self.base_url)

        elif self.provider == AIProvider.ANTHROPIC:
            # SECURITY: validate key format
            if not re.match(r'^sk-ant-[A-Za-z0-9_-]{20,}$', self.api_key):
                raise ValueError("Invalid Anthropic API key format")
            import anthropic
            return anthropic.Anthropic(api_key=self.api_key, base_url=self.base_url)
            # NOTE: Anthropic has no embeddings API — calling generate_embedding raises NotImplementedError

        elif self.provider == AIProvider.AZURE_OPENAI:
            # SECURITY: validate Azure key format (32 hex chars)
            if not re.match(r'^[a-fA-F0-9]{32}$', self.api_key):
                raise ValueError("Invalid Azure OpenAI API key format")
            return openai.AzureOpenAI(
                api_key=self.api_key,
                azure_endpoint=self.base_url,
                api_version="2024-02-01"   # ← hardcoded; do not change without testing
            )
```

**Key details:**
- The Ollama client calls `.list()` on construction — this is the liveness check, not a separate ping
- API key patterns are validated server-side before making any network call
- Azure API version is `"2024-02-01"` — hardcoded in the original, intentional

### 11.2 Ollama model matching uses `startswith()`, not exact match

Ollama reports models with version suffixes (e.g. `llama3.1:8b:latest`, `nomic-embed-text:v1.5`). The validation logic must use `startswith()` or the models will never be found:

```python
# WRONG — breaks if model has version suffix
if self.chat_model in available_models: ...

# CORRECT — matches "llama3.1:8b" against "llama3.1:8b:latest"
chat_found = any(model.startswith(self.chat_model) for model in available_models)
embed_found = any(model.startswith(self.embedding_model) for model in available_models)
```

### 11.3 OpenAI embeddings are batched; Ollama are one-at-a-time

```python
# OpenAI: one API call for the whole list
response = client.embeddings.create(model=self.embedding_model, input=texts)
embeddings = [e.embedding for e in response.data]

# Ollama: must loop — no batch endpoint
embeddings = []
for text in texts:
    response = client.embeddings(model=self.embedding_model, prompt=text)
    embeddings.append(response["embedding"])
```

The in-process deduplication cache (`_EMBED_CACHE` in `recommendations.py`) is critical for performance with Ollama — without it, every run re-embeds the same variable names.

### 11.5 CSV parsing must handle non-standard delimiters (`clevercsv`)

The existing upload handlers use `clevercsv.Sniffer` to auto-detect delimiters. Standard `pd.read_csv` will fail silently on semicolon-delimited or tab-delimited CSVs (it will parse them as one-column DataFrames with no error).

```python
import clevercsv

def read_csv_robust(content: str) -> pd.DataFrame:
    """Parse CSV with automatic delimiter detection."""
    try:
        dialect = clevercsv.Sniffer().sniff(content[:4096], verbose=False)
        return pd.read_csv(io.StringIO(content), sep=dialect.delimiter)
    except Exception:
        # Fallback to pandas default (comma)
        return pd.read_csv(io.StringIO(content))
```

This is called instead of `pd.read_csv` in both the codebook and study variable upload endpoints.

### 11.6 `dataset_variables_auto_completed.csv` is the required input for embedding

The embedding step (`embed_study`) reads from `dataset_variables_auto_completed.csv`, NOT from the raw `dataset_variables.csv`. This means the description-generation step (Phase 2) must always run before the embedding step (Phase 3), even if all variables already have descriptions:

```python
# generate_descriptions.py — if all descriptions are present, just copy the file
if not to_do:
    variables_df.to_csv(f"input/{study}/dataset_variables_auto_completed.csv", index=False)
    continue  # skip LLM calls, but still create the file
```

If the `_auto_completed.csv` file doesn't exist, the embedding step will raise `FileNotFoundError`.

### 11.7 Available studies detection

Studies are detected by listing directories in `input/` that are not hidden (don't start with `.`) and that don't start with `_`. Flat files in `input/` (like `target_variables.csv`) are ignored:

```python
import os

def list_studies() -> list[str]:
    input_path = "input"
    if not os.path.exists(input_path):
        return []
    return [
        name for name in os.listdir(input_path)
        if os.path.isdir(os.path.join(input_path, name))
        and not name.startswith(".")
    ]
```

### 11.8 `split_var_confidence` — the separator format

Recommendation keys in the UI are formatted as `"{description} - {confidence}%"` (single space, dash, single space). When parsing them back into `(codebook_var, confidence)` pairs:

```python
def split_var_confidence(value: str) -> tuple[str, str | None]:
    # Prefer " - " (single space) over "  - " (double space) 
    # Use rsplit to avoid breaking variable names that contain " - "
    if " - " in value:
        left, right = value.rsplit(" - ", 1)
        return left, right
    if "  - " in value:
        left, right = value.rsplit("  - ", 1)
        return left, right
    return value, None
```

The `rsplit(..., 1)` is intentional — variable names and descriptions can themselves contain ` - ` (e.g. `"Blood pressure - systolic"`), so splitting from the right is the only safe approach.

### 11.9 The `*` prefix on AI-generated descriptions

Descriptions generated by the LLM are prefixed with `*` in the stored CSV:
```

```
This distinguishes machine-generated descriptions from human-provided ones. Downstream code does not strip this prefix — it appears in the UI and in exports. It is intentional and should be preserved.
